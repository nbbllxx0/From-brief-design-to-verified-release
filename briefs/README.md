# X2 task suite (draft 2: briefs b01–b50)

Generated by `scripts/make_briefs.py` (re-run it to regenerate; edit tasks there, not here).

Each task has:
- `bNN_slug.md`: the brief, written as an engineer would write it. This is the only text an agent sees.
- `intended/bNN_slug.json`: the intended reading, drafted by Claude and **to be adjudicated by the author**. It contains:
  - `spec`: the intended spec (agentto.spec/v0);
  - `expected`: what a correct agent does:
    - `solve`;
    - `clarify`: the brief is missing or ambiguous on something that changes the design;
    - `refuse`: the brief cannot be solved as stated;
  - `oracle`: scripted answers to the clarification questions the brief warrants (used by the G+C conditions);
  - `admissible`: other readings with the reason. A reading that counts carries its own `spec`, and the scorer
    (`bench.match_task`) credits a match with it. Its consequence-weighted error is still measured.
  - `source`: a published benchmark family it restates, or `engineering` for a requirements-sheet-style brief;
  - `accept_warnings` (rare): rule warnings the task explains in its `notes`.

## Conventions (decided 2026-10-30)

- **Volume fraction** means the share of the design (non-passive) volume, as in commercial TO tools (the schema's
  `volume_fraction`). Every brief says "volume fraction 0.3" instead of "30% material", so the briefs carry no
  unintended ambiguity about it. In the draft X2 run, "20% material" with keep-in solids was read two ways.
- **Units**: specs are compared in mm and N. A spec written in other units, or converted from them, is the same
  problem if it converts to the intended one. A resolution given as `h` or as `cells_short_edge` is the same if it
  gives the same grid.
- **Restated benchmarks** keep the published load and support layout of their family. The dimensions and loads are
  ours, in physical units, so cite the family, not a figure. Check each `source` before citing it.

`tests/test_briefs.py` checks that:
- every intended spec validates;
- the rule base agrees with `expected`: clean for `solve` and `clarify`, at least one error for `refuse`.

`tests/test_bench_units.py` checks:
- the unit-converted specs and the admissible specs;
- each refuse task's rule code.

`scripts/validate_suite.py` solves every non-refuse intended spec cold at its preview rung on the GPU and writes
`results/X2/suite_check.json`.
